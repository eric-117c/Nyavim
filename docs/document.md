# document 模块

一个缓冲区 = 一段文本 + 一个光标 + 它在磁盘上的身份。它不认识按键、模式和终端，因此每条编辑规则都能在无 tty 的环境里测试。

## 契约

- **位置**：`Pos { line, col }`，列以字符计（不是字节、不是显示格）。显示宽度由 `ui` 用 `unicode-width` 与 tab 展开折算 —— `document` 不关心字符有多宽。
- **列的上界**：插入模式下光标可以停在行尾之后（`line_len`），普通模式用 `clamp_normal()` 收到最后一个字符上，避免出现按了没反应的“幽灵光标”。
- **区间**：所有范围操作取半开区间 `[a, b)`，`ordered()` 负责把两个位置排成文本顺序；算子范围因此不需要关心方向。
- **行**：`line_count()` 不把结尾换行产生的幽灵空行算作一行；`line(i)` 返回去掉行尾符的字符串。删除整行按原始 rope 行处理，避免在“文件以换行结尾”时留下多余的空白行。
- **motion**：`w`/`b` 跨行、按“空白 / 词字符 / 标点”三类分组；`h`/`l` 不出本行（与 vim 一致）；垂直移动把列夹到目标行长度。
- **撤销**：`checkpoint()` 记录一次可回退点，`undo()`/`redo()` 在快照间移动。快照粒度由调用方（`app`）决定，模块本身不做“合并相邻编辑”之类的猜测。
- **脏判定**：只有 `revision != saved_revision` 才算脏，因此撤销回到保存点时缓冲自动变干净。

## 已知限制

- `cw` 用“回退尾部空白”实现 vim 的“只改词、不吃后随空格”语义，因此跨行的 `cw` 与 vim 略有差异。
- 撤销上限固定为 200 步 / 8 MiB，没有配置项。
